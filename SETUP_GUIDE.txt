================================================================================
  TEXT-TO-SQL — SETUP GUIDE
================================================================================

PREREQUISITES
  - Docker + Docker Compose
  - PostgreSQL server (with superuser access) to host the internal metadata DB
  - An OpenAI-compatible LLM endpoint (e.g. vLLM, Ollama)


────────────────────────────────────────────────────────────────────────────────
  STEP 1 — Configure env/.env
────────────────────────────────────────────────────────────────────────────────

    cp env/.env.temp env/.env

Fill in env/.env:

  LLM_BASE_URL              URL of your LLM endpoint, e.g. http://host/v1
  LLM_MODEL                 Model name as returned by GET /v1/models
  METADATA_DB_HOST          Host of the PostgreSQL server for the internal DB
  METADATA_DB_PORT          Port (default: 5432)
  METADATA_DB_PASSWORD      Password for the app user (created automatically)
  METADATA_DB_ADMIN_USER    Superuser name (default: postgres)
  METADATA_DB_ADMIN_PASSWORD  Superuser password
  DB_CRED_ENCRYPTION_KEY    Secret key to encrypt target DB passwords at rest.
                            Generate one with: openssl rand -base64 32
  JWT_SECRET_KEY            HS256 secret — must match your auth system
  MIN_RELEVANCE_SCORE       Cosine similarity cutoff (default: 0.5)


────────────────────────────────────────────────────────────────────────────────
  STEP 2 — First run (creates internal DB, then exits)
────────────────────────────────────────────────────────────────────────────────

    docker compose --env-file env/.env up

Creates the internal database (nl2sql_metadata), applies migrations, then exits
asking you to register a target database. This is expected.


────────────────────────────────────────────────────────────────────────────────
  STEP 3 — Register your target database
────────────────────────────────────────────────────────────────────────────────

    psql -h <METADATA_DB_HOST> -p <METADATA_DB_PORT> -U postgres -d nl2sql_metadata

    INSERT INTO registered_databases
        (db_name, host, port, schema_name, description, db_user, db_password_encrypted)
    VALUES (
        'YOUR_DB_NAME',
        'YOUR_DB_HOST',
        5432,
        'public',
        'Short description',
        'YOUR_DB_USER',
        pgp_sym_encrypt('YOUR_DB_PASSWORD', 'YOUR_DB_CRED_ENCRYPTION_KEY')
    );

  YOUR_DB_USER needs SELECT access on all tables you want indexed.
  YOUR_DB_CRED_ENCRYPTION_KEY must match DB_CRED_ENCRYPTION_KEY in env/.env.


────────────────────────────────────────────────────────────────────────────────
  STEP 4 — Second run (indexes your DB and starts the API)
────────────────────────────────────────────────────────────────────────────────

    docker compose --env-file env/.env up

Indexes all tables (DDL, columns, FK relationships, embeddings), then starts
the API on port 8080. Wait for:
    INFO | Uvicorn running on http://0.0.0.0:8080

  [Optional] After indexing, you can enrich table and column descriptions
  using the LLM. Stop the API (Ctrl+C), then run:

    # Fill empty descriptions only (safe to re-run anytime)
    docker compose --env-file env/.env run --rm api describe

    # Overwrite all existing descriptions
    docker compose --env-file env/.env run --rm api describe --force

    # Specific database or language (default: Azerbaijani)
    docker compose --env-file env/.env run --rm api describe --db YOUR_DB_NAME --lang en

  Then restart the API:
    docker compose --env-file env/.env up


────────────────────────────────────────────────────────────────────────────────
  STEP 5 — Grant employee access to tables
────────────────────────────────────────────────────────────────────────────────

    psql -h <METADATA_DB_HOST> -p <METADATA_DB_PORT> -U postgres -d nl2sql_metadata

    -- Get the db_id
    SELECT id FROM registered_databases WHERE db_name = 'YOUR_DB_NAME';

    -- Grant access
    INSERT INTO emp_table_access (emp_id, db_id, table_name)
    VALUES (<emp_id>, <db_id>, 'table_one'),
           (<emp_id>, <db_id>, 'table_two');

Repeat for each employee. An employee with no rows here will get 403 from the API.


────────────────────────────────────────────────────────────────────────────────
  STEP 6 — Test the API
────────────────────────────────────────────────────────────────────────────────

    curl -X POST http://localhost:8080/generate \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer <JWT_TOKEN>" \
      -d '{"db_name": "YOUR_DB_NAME", "prompt": "How many employees are there?", "top_k": 5}'


────────────────────────────────────────────────────────────────────────────────
  RESTARTING
────────────────────────────────────────────────────────────────────────────────

    docker compose --env-file env/.env up

Skips indexing (already done), starts API directly.
Adding a new row to registered_databases triggers indexing on next restart.


────────────────────────────────────────────────────────────────────────────────
  TROUBLESHOOTING
────────────────────────────────────────────────────────────────────────────────

  403 on queries          → emp_id has no rows in emp_table_access (Step 5)
  "No relevant tables"    → Question is off-topic or MIN_RELEVANCE_SCORE is too high
  Indexing failed         → Wrong credentials or DB user lacks SELECT access
  LLM errors              → Check LLM_BASE_URL in env/.env; verify with:
                            curl <LLM_BASE_URL>/models
